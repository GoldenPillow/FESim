# 설계 문서 수명 규칙 (정본)

> design/ = "아직 안 지어진 것"의 집. **설계 문서는 todo다 — 코드가 되는 순간 죽는다.**
> 집행기 = tools/doccheck (./dev done에 포함, 어기면 레드).

## 수명 사이클

```
초안(draft) → 구현중(building, §0 체크리스트로 진행 추적)
  → 디자인 확정·구현 완료
  → ①같은 작업에서: 결정 요지 1줄을 registers/decisions.md에 등재
     ②정본을 코드로 흡수: 스키마·계약 = 타입, 규칙 = 테스트+독스트링 (산문 복사 금지)
     ③frontmatter status: done → ./dev gc 실행 = design/에서 삭제(archive/로 이송)
```

- **체크리스트 운용**: building 문서의 §0 체크리스트가 todo 정본. 항목 완료 시 체크,
  마일스톤·절 단위로 전부 체크되면 그 절부터 죽인다(부분 흡수 = 절 삭제 + decisions 1줄)
- **☠design/에 done 문서 방치 금지** — doccheck가 레드를 낸다. 삭제(이송)는 ./dev gc가 수행
- **frontmatter 필수**: `status: draft|building|done` + `target:`(코드가 될 자리). 없으면 레드
- 애매한 죽음은 삭제 대신 문서 머리에 `PENDING-KILL(사유·날짜)` — 확정 시 gc, 부활 시 표식 제거
- archive/는 무덤(이력 보존용) — 사람이 직접 넣지 않는다. 완전 폐기가 필요하면 별도 지시로만

## 이 규칙의 이유

산문 명세가 코드와 이중화되면 정본이 두 벌이 된다(직전 프로젝트 실증). 문서는 합의를 만드는
도구이고, 합의가 코드가 되면 문서의 역할은 끝난다 — 남기면 반드시 코드와 어긋난다.
