# 엔트리 빌더 — 반지·계승 스킬의 글로벌 세팅

착수 2026-09-08 · 상태 **결정 완료 — 구현 중**
발단 = 사용자 지시 *"스킬과 반지도 글로벌에 세팅가능하도록 설계"*.

> ☠이 문서는 합의를 만드는 도구다. 구현이 끝나면 요지 1줄을 registers/decisions.md에 남기고
> 정본은 코드(타입·테스트)로 흡수한 뒤 `./dev gc`로 죽인다(rules/design-lifecycle.md).

## 1. 지금의 층 (코드에서 읽은 실측)

빌더의 값은 **세 층**이고, 지금 반지·계승 스킬만 글로벌 층이 없다.

| 값 | 글로벌(비교 슬롯) | 카드 개별 | 잠금 스냅샷 |
|---|---|---|---|
| 직업·내부 레벨 | `BuilderSlot.jid` / `.internal`(+ 전역 `internal`) | `cardClass[pid]` | `EntryLock.jid/internal` |
| 무기·강화·각인 | `BuilderSlot.iid/plus/engrave` | `overrides["pid:li"]` | `EntryLock.iid/plus/engrave` |
| **반지(gid·絆)** | **없음** | `rings[pid]` | `EntryLock.gid/bond` |
| **계승 스킬 2칸** | **없음** | `inherits[pid]` | `EntryLock.skills` |

코드가 이미 그 결손을 적어 두고 있다 — `followGlobal()` 주석:
*"반지·계승 스킬은 글로벌 짝이 없어 남긴다"*.

해석 규칙(현행) = **카드 개별 → 글로벌 슬롯 → 기본값**. 잠금 카드는 스냅샷만 읽는다.
유령 카드(잠긴 pid의 대기 사본)는 **카드 개별값을 전부 무시하고 글로벌만** 받는다 —
그래서 지금 유령은 반지가 항상 없다(비교 기준이 어긋나는 자리).

상단 컨트롤 1행(메인 슬롯) = `[클래스][내부레벨][무기][강화][각인]` + `+ 멀티클래스 비교`.
2행부터(비교 슬롯)는 레전드 없이 같은 컬럼에 선다.

## 2. 하려는 것

반지·계승 스킬에 글로벌 층을 만들어 **"전원 마르스 絆20 + 속도+4/회피+20 기준으로 비교"** 가 되게 한다.
부수 효과로 유령 카드가 글로벌 반지·스킬을 받아 비교 기준이 맞는다.

## 3. 설계 (권장안)

### 3-1. 저장 형태 = `BuilderSlot` 확장
```ts
export interface BuilderSlot {
  jid: string;
  internal?: number;
  iid?: string; plus?: number; engrave?: string;
  gid?: string; bond?: number;          // ← 신설: 문장사 반지 + 絆
  skills?: [string, string];            // ← 신설: 계승 2칸(sid, "" = 빈 칸)
}
```
- `parseSlots` 코덱 확장이 **강제된다** — `SNAP_CODEC`의 `satisfies` 전수성 게이트가
  필드를 더하고 코덱을 안 더하면 typecheck를 즉시 레드로 만든다(guestSave.ts).
- `BuilderSnapshot`에 새 최상위 필드를 만들지 **않는다**: 슬롯 안에 두면 기존 장비와 같은 층이라
  `followGlobal`·`carriedEquip`·리셋·프리셋 왕복이 이미 있는 규칙 하나로 덮인다.
  최상위에 두면 "슬롯 밖 글로벌"이라는 **세 번째 층**이 생겨 우선순위가 두 벌이 된다.
- 구 저장분 호환 = 두 필드 모두 선택 필드라 없으면 "글로벌 없음"(현행 동작 그대로).

### 3-2. 해석 = 기존 규칙 그대로 한 줄 추가
```
반지     = rings[pid]      ?? slots[li].{gid,bond} ?? 없음
계승 2칸 = inherits[pid]   ?? slots[li].skills     ?? ["",""]
```
잠금 카드는 스냅샷(`EntryLock.gid/bond/skills`)만 읽는다 — 변경 없음.
유령 카드는 카드 개별을 무시하므로 **글로벌 값을 받는다**(이번 개편의 실익).

### 3-3. 전파 = 장비와 같은 규약
`followGlobal()`이 지금 `cardClass`·`overrides`를 걷는다. 여기에 **반지·계승도 걷는다**를 더한다
— 글로벌을 바꾸면 대기 카드가 전부 따라오고, 카드에서 손대는 순간 그 카드만 분기한다
(2026-09-05 확정 규약: *"글로벌 변경 = 대기 카드 전부 추종, 엔트리(잠금) 카드만 불변"*).
☠걷는 범위는 미결 Q5.

### 3-4. UI = 상단 컨트롤 4개 추가
슬롯 행이 `[클래스][내부레벨][무기][강화][각인]` → `[클래스][내부레벨][무기][강화][각인][반지][絆][스킬1][스킬2]`.
컨트롤 5 → 9개. 컨테이너가 `flex-wrap`이라 좁으면 2행으로 접힌다 — 배치는 미결 Q4.
- 반지 드롭다운·絆 드롭다운·계승 드롭다운은 **카드에 있는 것을 그대로 쓴다**
  (`ringOptionsOf` · `BondDropdown` · `inheritOptions`) — 목록·스포일러/DLC 체커 준수가 한 곳이다.
- 계승 2칸의 "다른 칸 sid 비활성" 규칙도 그대로 재사용한다.

### 3-5. 건드리지 않는 것
- `EntryLock` 스키마 · 공유 산출물(HTML·카드 이미지) 스키마 — 해석층만 바뀐다.
- 엔진 배선 — 계승 2칸은 이미 스탯·전투력에 반영된다(2026-09-08 확정: 고유 2칸은 표시 전용).

## 3-6. ★라인 >0의 반지·스킬은 누가 보여주는가 (설계 결론)

카드의 반지 행·계승 2칸은 **라인 0에만** 있다(반지 행은 `li === 0`에서만 그려진다).
글로벌이 슬롯별이면 라인 li는 슬롯 li의 반지·스킬을 받는데 그 라인엔 표시 자리가 없다.

→ **상단 슬롯 행이 표시 담당이다.** 이미 규약이 그렇다: *"슬롯마다 헤더 성장률 행 1줄 +
캐릭터마다 본문 라인 1줄 — 두 줄의 순서 동치"*(2026-08-31). 상단 컨트롤 행도 같은 순서이므로
"라인 2의 반지 = 2번째 슬롯 행의 반지"가 규칙이다. 결손이 아니라 배치다.

카드 개별(`rings`/`inherits`)은 **pid 단위 그대로**(라인 무관) — 라인별 개별 편집은 모델에 없다.
실효값 = `카드 개별 → 슬롯 li → 없음`.

☠`compares`는 **jid가 있는 슬롯만** 라인을 만든다(빈 jid는 라인을 안 만든다) — 그래서 `slots[li]`로
바로 색인하면 어긋난다. `compares[li].slot`으로 원본 슬롯을 찾고, 직업 미선택(compares 비어 있음)
이면 1라인 = 메인 슬롯이다.

| Q5 전파 | **장비와 동일 · 축별** — 글로벌 반지를 바꾸면 카드 반지만, 글로벌 스킬을 바꾸면 카드 스킬만 걷는다 |

### 원문 (기각안 포함 — 이력)

### Q1. 글로벌 반지·스킬을 **슬롯별**로 둘 것인가, **전역 하나**로 둘 것인가
- 배경: 무기는 슬롯별이다(직업마다 들 수 있는 무기가 달라서). 반지·스킬은 직업과 무관하다.
- 선택지:
  (1) **슬롯별**(`BuilderSlot`에 동봉) — "소드마스터+마르스 vs 세이지+시구르드" 비교가 된다.
  (2) **전역 하나**(스냅샷 최상위 필드) — 컨트롤이 1벌이라 상단 바가 덜 길어진다.
- 권장: **(1) 슬롯별**. 전역 하나는 슬롯별의 부분집합이고(슬롯 1개만 쓰면 같다), 층을 새로
  만들지 않아 우선순위 규칙이 한 벌로 유지된다. 대가 = 비교 슬롯마다 컨트롤 4개가 붙는다.
- 안 정하면 막히는 것: 저장 스키마(§3-1)와 UI 배치(Q4) 둘 다.

### Q2. 상단 바 배치 — 컨트롤 9개를 어떻게 세울 것인가
- 배경: 지금 1행에 5개가 서고 좁으면 wrap된다. 9개면 넓은 화면에서도 2행이 될 가능성이 높다.
- 선택지:
  (1) 그냥 이어 붙인다(wrap에 맡김)
  (2) **줄을 갈라 그룹**: 1줄 `[클래스][내부레벨]` / 2줄 `[무기][강화][각인]` / 3줄 `[반지][絆][스킬1][스킬2]`
  (3) 반지·스킬을 접이식(토글 "고급 설정")으로 감춘다
- 권장: **(2)**. 슬롯이 여러 개일 때 컬럼 정렬이 이미 규약이라(레전드는 1행만), 그룹으로 갈라야
  비교 슬롯 행이 가로로 안 터진다.
- 안 정하면 막히는 것: 상단 바 마크업 전체. ☠실측(폭·wrap)이 필요하다 — 승인 후 헤드리스로 잰다.

### Q3. 글로벌 반지의 絆 기본값
- 배경: 카드 반지는 선택 시 絆 20이 기본이다(현행). 글로벌도 같게 할지.
- 선택지: (1) 20 고정 기본 (2) 1 기본 (3) 카드와 같은 20 + 상단에서 바로 조절
- 권장: **(3)** — 카드 규약을 그대로 따르고 상단 絆 드롭다운으로 즉시 바꾼다.
- 안 정하면 막히는 것: 없음(구현 중 조정 가능).

### Q4. 반지 "1인 1개" 규칙을 글로벌에 어떻게 말할 것인가
- 배경: 실게임은 반지 1개를 한 명만 낀다. 글로벌은 **전원이 같은 반지를 낀 가정**이라 실전 불가 상태다.
  지금도 카드마다 같은 반지를 고를 수 있어 이미 그런 상태를 만들 수 있다.
- 선택지: (1) 아무 말 안 한다(현행과 동형) (2) 상단에 각주 한 줄 (3) 중복 경고 표식
- 권장: **(1)** — 이 표는 "가정 비교기"이고 이미 같은 규칙으로 굴러간다. 새 경고는 소음이다.
- 안 정하면 막히는 것: 없음.

### Q5. 글로벌을 바꿀 때 카드 개별 반지·스킬을 걷을 것인가
- 배경: 장비는 걷는다(`followGlobal`) — 글로벌을 만지면 대기 카드가 전부 따라온다.
  반지·스킬은 지금 글로벌이 없어 안 걷힌다.
- 선택지:
  (1) **장비와 동일** — 글로벌 반지를 바꾸면 카드 개별 반지를 전부 걷는다(스킬도 각각)
  (2) 걷지 않는다 — 카드에서 손댄 것은 계속 이긴다
- 권장: **(1)**. 규약이 하나여야 한다. ☠단 **축별로** 걷는다(반지를 바꿔도 카드 계승 스킬은 안 걷는다)
  — 장비도 `overrides`만 걷고 `cardClass`는 따로 걷는 것과 같은 결이다.
- 안 정하면 막히는 것: `followGlobal` 시그니처(축 인자 추가 여부).

## 5. 구현 중 드러난 것 (☠조용한 실패 하나를 막았다)

**카드에서 반지·스킬을 "없음"으로 지우는 것**이 글로벌 도입으로 표현 불가가 된다 —
지금은 "키 삭제 = 없음"인데, 글로벌이 생기면 키를 지우는 순간 **글로벌로 되돌아간다**.
사용자 눈에는 *"지웠는데 안 지워진다"*로 보이고 오류도 경고도 없다.

→ **명시적 없음**을 값으로 표현한다: 반지 `{ gid: "", bond: 20 }` · 계승 `["", ""]`.
글로벌이 없을 때는 종전대로 키를 지운다(저장분이 깨끗하게 유지된다 = 기존 사용자 무변화).
해석 규칙은 컴포넌트 밖 순수 함수로 뽑았다(`effectiveRing` / `effectiveSkills`) — 층 우선순위는
**규칙**이고, 렌더 안에 흩어지면 층마다 다르게 적힌다. 경계는 테스트가 지킨다.

부수로 두 곳이 더 고쳐졌다(둘 다 글로벌 도입 없이는 안 나던 결손):
- `patchWaitRing`의 絆 변경이 `prev[pid]`만 보고 있었다 — 글로벌에서 온 반지의 絆이 **조용히 무시**된다.
  기준을 실효값으로 바꿨다.
- `patchInherit`가 카드 키가 없을 때 빈 칸에서 시작했다 — 글로벌 2칸 중 하나만 바꾸면
  **나머지 한 칸이 조용히 지워진다**. 씨드를 실효값으로 바꿨다.
- `toggleLock` 스냅샷이 세션 맵만 읽었다 — 글로벌로 낀 반지·스킬이 **잠그는 순간 사라진다**.
