## 0. 왜 필요한가

`tools/replay/policy.mjs`는 **매 턴 국소 최적**만 본다 — 죽지 않는 수 중 점수가 높은 것을 고른다.
그래서 프롤로그~4장을 무손실로 이기긴 해도 **인게임 정석과 다른 길**로 이긴다.
사용자가 준 정석 수순은 전부 **선수(先手) 계획**이고, 국소 최적으로는 절대 안 나온다:

| 장 | 사용자가 지시한 오프닝 |
|---|---|
| m002 | 1턴 평타로 **우측 도끼병** · 2턴 인게이지 발동 후 뤼미에르에게 **스타 러시** |
| m003 | 1턴 인게이지 → 바로 위쪽 검병에게 평타 |
| m004 | 1턴 셀린이 **워프라이나로 요새 칸 이동 → 2칸 위 궁병 격파** · 클로에는 인접 마법사 격파 · 2턴 인접 민가 |

이런 수는 "지금 이득"이 아니라 **판을 여는 수**다(궁병을 먼저 지우면 비병의 위협이 사라진다).
휴리스틱을 아무리 조여도 안 나오므로, **사람이 수순을 적고 정책이 그 뒤를 잇는** 구조가 맞다.

## 1. 설계 원칙

1. **오프닝은 데이터다** — 코드가 아니라 `data/fe17/openings/{cid}.json`. 챕터마다 파일 하나.
   ☠파이프라인 산출물이 아니라 **사람이 쓰는 정본**이므로 `data/fe17/` 안이되 변환 대상에서 뺀다.
2. **정책은 심판이 아니다** — 합법성은 엔진이 소유한다. 오프닝이 낸 액션이 거부되면
   **조용히 넘어가지 않고** 실패로 보고한다(잘못된 수순을 눈치 못 채면 기보가 조용히 어긋난다).
3. **좌표를 직접 쓰지 않는다** — 인계 사슬로 로스터·레벨이 바뀌면 좌표가 흔들린다.
   대상은 **pid·방향·거리**로 지시하고, 착지 칸만 좌표를 허용한다.
4. **오프닝이 끝나면 정책이 잇는다** — 오프닝은 앞 몇 턴만 소유하고, 그 뒤는 기존 휴리스틱.
5. **부분 지시 허용** — 한 턴의 모든 유닛을 적을 필요가 없다. 지시된 유닛만 먼저 두고
   나머지는 그 턴에도 정책이 둔다.

## 2. 스키마 초안

```jsonc
{
  "cid": "m002",
  "note": "사용자 지시 2026-08-18",
  "turns": [
    {
      "turn": 1,
      "steps": [
        { "unit": "PID_リュール", "attack": { "pid": "PID_M002_幻影兵_アクスファイター_イベント" } }
      ]
    },
    {
      "turn": 2,
      "steps": [
        { "unit": "PID_リュール", "engage": true },
        { "unit": "PID_リュール", "art": { "pid": "PID_M002_ルミエル" } }
      ]
    }
  ]
}
```

### 2-1. step 문법 (한 유닛의 한 수)

| 키 | 뜻 | 엔진 액션 |
|---|---|---|
| `unit` | 행동 주체 **pid**(id가 아니다 — 사슬로 순번이 바뀐다) | — |
| `engage: true` | 인게이지 발동(행동 무소모) | `engage` |
| `attack: { pid, weapon? }` | 통상 공격. 사거리 안으로 **최소 이동** 후 친다 | `move` + `attack` |
| `art: { pid, land? }` | 인게이지 기술. 리워프형이면 `land`(착지 칸) 필수 | `move`? + `engageAttack` |
| `move: { to }` | 이동만 | `move` |
| `visit: true` | 민가 방문(그 칸까지 이동 후) | `move` + `visit` |
| `item: { iid }` | 소모품 사용 | `item` |
| `wait: true` | 대기 | `wait` |

`to`·`land`의 값 문법 — **좌표는 마지막 수단**이다:

```jsonc
"to": { "x": 8, "y": 4 }                  // 절대 좌표
"to": { "near": "PID_...", "dir": "up" }  // 그 유닛의 위 칸
"to": { "tid": "TID_砦", "nearest": true } // 가장 가까운 요새 칸
```

### 2-2. 대상 지정 — pid가 유일한 정본

`"pid"`는 dispos pid다. **같은 pid가 여러 유닛인 챕터가 있으므로**(m003 `ソードファイター` 3인)
동명이인은 보조 키로 가른다:

```jsonc
{ "pid": "PID_M003_イルシオン兵_ソードファイター", "pick": { "nearestTo": "PID_リュール" } }
{ "pid": "...", "pick": { "dir": "up", "of": "PID_リュール" } }   // 그 유닛 기준 위쪽
```

☠**사용자 지시는 "우측 도끼병"·"2칸 위 궁병"처럼 방향으로 온다.** `pick`이 그 말을 그대로 받는
자리다 — 오프닝 파일을 쓸 때 사람이 방향으로 쓰고, 해석은 도구가 한다.

## 3. 실행 계약

```
playerPhase(turn):
    ops = opening?.turns.find(t => t.turn === turn)?.steps ?? []
    for op of ops:
        unit = 국면에서 pid로 찾는다      // 없으면 실패
        actions = resolve(op, 국면)       // 좌표·대상 해석
        for a of actions: dispatch(a)
        if 국면이 안 바뀌었다: 실패 보고   // ☠조용한 통과 금지
    // 오프닝이 끝난 뒤 남은 유닛은 기존 휴리스틱이 둔다
```

- **실패 = 도구 종료코드 1** + 사유 출력(`오프닝 m002 T1 #0: PID_... 공격 거부 — 사거리 밖`).
  기보는 쓰지 않는다(잘못된 오프닝으로 만든 기보가 정본이 되면 안 된다).
- `--no-opening` 플래그로 끄고 순수 휴리스틱과 비교할 수 있어야 한다(수순의 효과 측정).

## 4. 도구 인터페이스

```
./dev replay <cid> --seed <n> --carry <앞 기보>          # 오프닝 파일이 있으면 자동 적용
./dev replay <cid> --no-opening                          # 무시하고 휴리스틱만
./dev opening check <cid>                                # 해석만 해보고 좌표·대상을 출력(수순 검수)
```

`./dev opening check`가 있어야 사용자가 지시한 수순이 **우리 국면에서 무엇을 가리키는지**
확인하고 고칠 수 있다(m002 "우측 검병"이 실제로는 도끼병이었던 것 같은 어긋남을 미리 잡는다).

★구현 시 정정(2026-08-18) — check는 **해석만** 하지 않고 판을 끝까지 돌린다. 2턴 이후 수순의 해석은
그 턴의 국면이 있어야 서기 때문이다(1턴만 풀면 뒷 턴은 영영 검수 못 한다). 대신 **기보를 쓰지 않는다**
(`--opening-check`가 기록을 막는다) — 검수는 부수효과 없이 끝난다. 인계·시드도 그대로 받는다:
`./dev opening check m004 --seed 5 --carry data/fe17/replays/m003.eph.json`.

### 4-1. 어휘 증보(구현에서 확정)

| 문법 | 뜻 |
|---|---|
| `pick: { dir, of? }` | 방향 지정. ☠**옆으로 덜 벗어난 쪽**이 먼저다(맨해튼만 보면 대각으로 멀리 있는 유닛이 이긴다 — m003 검병 2인) |
| `pick: { nearestTo }` · `pick: { at }` · `pick: { index }` | 근접·좌표·순번 지정(순번은 최후 수단) |
| `attack: { from }` | 발판을 못박는다(판을 여는 수 = 지나쳐서 치기). 그 칸에서 못 치면 실패 |
| `land: { tid, near }` | "그 궁병 밑의 요새 칸" — 지형으로 고르되 **기준은 다른 유닛**. 워프 착지는 이동이 아니므로 맵 전체가 후보다 |
| `visit: true` | 가장 가까운 미방문 민가. ☠서는 칸은 `stand`다(민가 본체는 통행 불가) |

★**소유 계약** = `engage`·`move`는 행동을 안 쓰므로 그 유닛을 정책에 넘긴다(이동한 유닛은 엔진 이동 예산이
0이라 정책이 되돌리지 못한다). `attack`·`art`·`visit`·`item`·`wait`는 행동을 쓰고 그 턴을 끝낸다.

## 6. 미결 (2026-08-18 종결·잔여 1건)

**A. 오프닝이 실패하면 어떻게 하는가** — 지금 설계는 **즉시 실패**(기보 안 씀)다.
대안 = 경고 후 휴리스틱으로 강하. → 권장 = 실패. 조용한 강하는 "지시대로 됐다"는 착각을 만든다.

**B. 오프닝의 범위** — 몇 턴까지 쓰는가. 지금 설계는 **사람이 쓴 만큼**이고 나머지는 휴리스틱이다.
전 턴을 다 적는 방식(완전 기보)도 가능하지만 그건 오프닝이 아니라 기보 편집기(M4) 몫이다.

**C. 시드와의 관계** — 오프닝이 있어도 명중·필살 난수는 시드가 정한다. 같은 오프닝이라도
시드에 따라 결과가 갈리므로 **오프닝 + 시드 탐색**을 병행한다(현행 `chain.sh`와 같은 구조).

**D. `pick`의 방향 어휘** — `up/down/left/right`가 **데이터 좌표계**(y+ = 화면 위, MP0a 확정)를
따른다는 것을 문서에 못박을지. → 권장 = 사용자 표기(화면 기준)를 그대로 쓰고 도구가 변환.

☠**A~D 전건 권장안 채택(2026-08-18 구현)** — A = 실패(기보 미기록·종료코드 1) · B = 사람이 쓴 만큼 ·
C = 오프닝 + 시드 탐색 병행(m004는 시드 5에서만 무손실) · D = 화면 기준 어휘 + 도구 변환.

**E. ☠m002 스타 러시를 어느 뤼미에르에게 두는가(사용자 확인 대기)**

★수순 정정(2026-08-18 사용자) = 1턴 도끼병 제거 · 2턴 궁병 제거 · 3턴 스타 러시. 앞 두 턴은 그대로 서고
(리월 = 도끼병 왼쪽 · 반드레 = 아래 · 크랑 = 왼쪽 아래 `optional`), 3턴만 남았다. 막는 것은 **1회전 종료 시점**이다:

- 2턴 적페이즈에 **뤼미에르가 리월에게 달려든다**(그가 준 피해 1). 리월의 반격 11 + 추격 11이 HP 18을 넘겨 그 자리에서 죽는다.
- 그 죽음이 `ルミエル撃破一回目_済`를 세워 **1회전이 끝난다** — 스크립트가 자군을 재배치하고
  `UnitSetEngageCount(리월, 0)`으로 **기공을 0으로 만든 뒤** 2회전 뤼미에르(6,14 · 시구르드 장착)를 세우고
  회복용 `TID_紋章氣`를 (8,4)에 깐다.
- ☠이 경로는 **스크립트가 전제한 정상 흐름**이다: `ルミエルから攻撃後死亡_済` 분기가 "뤼미에르가 공격한 뒤 죽었다"를
  따로 받는다. 우리 판이 어긋난 게 아니라 1회전이 2턴에 끝난 것이다.
- ⇒ 3턴에 칠 수 있는 뤼미에르는 **2회전(6,14)뿐**이고, 그때 기공은 0이라 (8,4) 紋章氣를 밟아 채운 뒤에야 발동한다.

선택지 = (1) 스타 러시를 **2회전 뤼미에르**에게 두고 턴을 그쪽에 맞춘다(紋章氣 경유 수순을 함께 적는다) ·
(2) 실기에서 1회전 뤼미에르가 2턴 반격에 죽지 **않는다면** 그 관측(그의 HP·리월 반격 피해)을 주면 수치를 다시 판독한다.
