## 1. 모델 — 저장 버튼이 없는 작업공간

프리셋 = **저장 버튼 없이 항상 자동 저장되는 빌더 화면 한 벌**. 활성 프리셋이 화면을 계속 따라가므로
미저장 변경·저장 버튼·*"저장하시겠습니까"* 대화가 통째로 없고, 빌드 A/B 왕복이 클릭 1회다.

근거 = 스펙 어디에도 저장 버튼이 없고, *"기존 프리셋 우측에 + 복사"* 가 있다는 것은 **현재 상태를 다른
이름으로 굳히는 행위를 복사 버튼이 이미 담당**한다는 뜻이다. 또 이 기능 최악의 사고는 시크릿 창에서
한 시간 쌓은 빌드가 새로고침에 사라지는 것인데, 자동 저장이 그 노출 시간을 최소화한다.
(반대안 = 명시 저장 버튼 + 전환 시 확인 대화 — §7 확정표에서 기각)

## 2. 스냅샷 범위 — 화면을 만드는 것 전부 (12종)

**담는 12종** (2026-09-05 사용자 확정)
- 구성 8종 = `slots` · `internal` · `sort` · `locked`(EntryLock[]) · `overrides` · `cardClass` · `rings` · `inherits`
- 체커 4종 = `star`(성옥의 가호) · `showGrowth`(고유 성장률) · `showSpoilers` · `showDlc`

**빼는 것** = UI 임시 상태 전부 — 포인터 흔적 · 팝업 열림 · 드래그 · sticky 실측 높이 등
(전수와 제외 사유는 심 가드 테스트의 `EXCLUDED`가 소유)

★**캐릭터 순번도 포함**(2026-09-05 사용자 지시). 실물 확인 = 순번은 별도 상태가 아니라 위 12종 안에 이미 있다:
- **엔트리(잠금) 순번** = `locked` **배열 순서**. 드래그 재정렬(`moveLock`)이 배열을 재배치하고
  `lockedDisplayRows`가 *"잠근 순서 그대로"* 소비한다.
- **대기 목록 순번** = `sort`(미지정이면 로스터 기본 순).

☠따라서 파서·정규화는 **배열 순서를 절대 건드리지 않는다**(정렬·중복 제거 금지). 원소 강하로 하나가
빠지면 나머지는 상대 순서를 유지한 채 앞당겨진다. 이 보장은 §6에 전용 테스트로 박제한다 —
왕복 `toEqual`만으로는 "우연히 같은 순서"와 구분되지 않으므로 **재정렬한 순서**로 왕복시킨다.

### 근거 (1) ★체커를 빼면 사고가 난다 — 사용자 판정 (2026-09-05)

*"체커를 빼면 성옥과 캐릭터가 빠지는 일이 발생하며 이는 사고이다"*.

체커는 이름과 달리 **표시 필터가 아니라 계산·모집단 입력**이다. 실물 확인:
- `star`(성옥의 가호) — 성장 경로 입력이라 **스탯 자체가 바뀐다**.
- `showSpoilers`/`showDlc` — 숨긴 문장사는 문장사 목록에서 빠져 **잠긴 엔트리의 絆 보너스가 소실**되고,
  숨긴 각인은 **무각인으로 강하**해 전투력이 달라진다. 숨긴 캐릭터는 **표에서 통째로 사라진다**.
- `showGrowth` — 블록 첫 줄의 개인 성장률 행 유무라 표의 행수가 바뀐다.

즉 체커가 프리셋 밖이면 **같은 프리셋인데 스탯도 모집단도 다른** 상태가 오류·경고 없이 성립한다.
전역 규약이 가장 비싸다고 부른 조용한 실패이고, 프리셋의 목적(빌드 한 벌의 재현)을 정면으로 깬다.

### 근거 (2) — "저장된 모든 상태"는 현황이 아니라 요구다

지금 영속인 것은 잠금과 체커 4개뿐이고, 화면의 나머지(글로벌 직업 라인·In.Lv·글로벌 장비·카드 개별 클래스·
개인 장비·반지·계승 스킬)는 **전부 세션 휘발**이다. 구성 8종을 빼면 프리셋 전환이 잠금 목록만 바꾸고
화면 상단은 그대로다 — 전환한 티가 안 나고, 스펙의 두 모드가 둘 다 의미를 잃는다(복사할 게 잠금뿐).

### 근거 (3) — 체커의 정본이 프리셋으로 옮겨간다

체커 4종은 **빌더 전용**이다(실측: `BuilderIsland` 밖 사용처 0건). 따라서 전역 키
`fesim:ui:{starsphere,pgrowth,spoilers,dlc}`를 **폐기하고 프리셋을 유일 정본으로 삼는다** —
같은 값이 전역 키와 프리셋 두 곳에 살면 *"전환 시 어느 쪽이 이기나"* 가 매번 결정 사항이 되고
정본이 두 벌이 된다(규약 위반). 마이그레이션이 잠금과 함께 4키를 Preset 001로 승격하고 제거한다.
`saveShowSpoilers` 등 저장 함수 4개는 비계로 걷는다(제거 조건 = §0 이월).

### ★올리셋 = 완전 초기 (2026-08-31 "체커 유지" 결정을 **대체**)

사용자 확정 = **새 프리셋(+ 추가)도 Reset All도 체커까지 전부 off**.
따라서 `emptySnapshot()`이 12종 전부의 초기값을 소유하고 `reset()`은 `applySnapshot(emptySnapshot())`
한 줄이 된다 — *"새 프리셋 = 올리셋 상태"* 는 **검사 대상이 아니라 정의**가 되고 예외가 0개다.
☠**2026-08-31의 "체커 저장값은 유지"(`reset()` 주석)를 이 결정이 대체한다** — `registers/decisions.md`에
대체 사실을 등재하지 않으면 규약이 조용히 이동한다.
안전측은 그대로다: 첫 방문(프리셋 없음) = 올리셋 = 스포일러·DLC 숨김.

`sort`는 순수 표시값이지만 `reset()` 정의역 안에 있어 담는다 — 빼면 위 항등이 깨져 예외가 하나 생긴다.

### ☠함정 — 기점을 건드리지 말 것

`internal`·`cardClass.internal` = **1기점 표기값** / `EntryLock.internal`·`compares.internal` = **0기점**.
스냅샷은 각 원 기점 그대로 담는다. 통일하려 들면 프리셋 왕복마다 1레벨 오차가 조용히 쌓인다.

## 3. 저장 스키마 — 인덱스 + 슬롯 2축

정본 = `lib/guestSave.ts`의 타입(여기 필드를 복제하지 않는다). 구조 결정만 적는다.

- 키 = `fesim:preset:fe17:index` + `fesim:preset:fe17:NNN` (3자리 패딩 = 기본 이름과 같은 주소)
- ☠**단일 키가 아닌 이유** — 자동 저장이 활성 슬롯 하나(~14KB)만 쓰고, 슬롯 하나가 깨져도 목록이 살아
  사용자가 스스로 다른 프리셋으로 빠져나간다. 단일 키였다면 JSON 한 글자 손상 = 전 빌드 소멸.
- ★`active`·`seq`를 **인덱스 봉투 안에** 둔다 — 별개 state로 들면 삭제 후 인덱스에 없는 키에 계속 쓴다
  (오류 없음·전손. 심사가 잡은 치명 결함이고, 봉투 안으로 넣으면 구조적으로 소멸한다).
- 쓰기 순서 = **슬롯 먼저, 인덱스 나중**. 인덱스 쓰기만 실패하면 그 빌드는 저장소에 살아 있는 채 목록에
  안 나오므로 `recoverOrphans`가 마운트마다 회수한다(고아 = 조용한 소실의 유일 경로).
- 번호는 **재사용하지 않는다** — 이름을 바꿔도 프리셋의 정체는 번호다(넘버링 세이브 규약 계승).
- ★**이름은 슬롯에도 굽는다** — 인덱스의 `name`은 목록 렌더용 캐시로 격하. 안 그러면
  **인덱스 1회 손상 = 전 프리셋 이름 영구 소실**이고 되살릴 근거가 저장소 어디에도 없다(비평 지적).
- 기본 이름 문자열(`Preset 001`)은 **저장물에 굽지 않는다** — `name: ""`로 두고 표시만 `presetName()`이
  답한다(번호 규약·로케일이 바뀌면 옛 프리셋에만 굳은 문자열이 남는다).
- 손상 슬롯은 **자동 삭제하지 않는다**(기보의 `readSave→dropSave`와 다른 유일한 지점) — 기보는 다시 둘 수
  있지만 빌드는 사용자가 손으로 쌓은 것이다. 목록에 "불러오지 못한 프리셋"으로 남겨 사용자가 지우게 한다.

### 마이그레이션 — 구 키 5개를 Preset 001로 승격

`fesim:ui:entrylocks` + 체커 4키(`starsphere`·`pgrowth`·`spoilers`·`dlc`)를 **함께** 승격하고 제거한다.
세션 상태(구성 8종 중 잠금 외)는 원래 새로고침에 휘발이었으므로 **초기값이 정확한 복원**이다 — 없던 것을
지어내지 않는다. ☠**승격 저장이 실패하면 구 키를 지우지 않는다** — 지우고 못 쓰면 사용자 데이터가 증발한다.
순서가 안전측을 정한다.

| 기존 상태 | 승격 후 |
|---|---|
| 잠금 3건 + 체커 2개 켬 | Preset 001에 잠금 3건 + 그 체커 2개 · 구 키 5개 삭제 |
| 잠금 0건 · 체커 전부 off | Preset 001 = 올리셋 · 지울 구 키가 없으면 removeItem 생략 |
| 구 잠금 키 손상(구버전 pid 문자열 배열) | 원소 강하가 걸러 빈 001 · **구 키는 남긴다**(강하 사실 보존) |
| 인덱스 손상, 슬롯 생존 | `recoverOrphans`가 슬롯에서 목록·이름 복구 · 001을 덮지 않는다 |
| 슬롯만 있고 인덱스 없음(부분 쓰기 실패) | 회수로 목록 복원 + 인덱스 재기록 |
| 저장 실패(시크릿·쿼터) | 구 키 **보존** · `failed: true` → 트리거 `!` + 목록 하단 레드 |

### 강하·검증

`loadEntryLocks`의 flatMap 본문을 `parseEntryLock`으로 뽑아 **프리셋 안 EntryLock 배열과 공유**한다
(강하 규칙의 답변자는 하나 — 두 벌로 적으면 반드시 하나가 낡는다).
`internal`·`bond`·`plus`는 **범위 클램프**한다 — `num()`이 `Number.isFinite`만 보면 손상값 `internal: 1e9`가
엔진 `growthPath`의 레벨업 루프에 들어가 탭이 오류 없이 정지한다(비평 지적).

## 4. UI

## 6. 이음매 — 누락이 생길 수 있는 경로는 넷, 넷 다 기계로 막는다

앞으로 `useState`가 하나 늘고 스냅샷에 안 담기면 그 값만 프리셋 전환에서 조용히 이월된다.
오류도 경고도 없다. 그래서:

| 경로 | 방벽 | 층 |
|---|---|---|
| 타입에 있는데 **파서**에 없다 | `SNAP_CODEC ... satisfies { [K in keyof Required<Snapshot>]: FieldCodec<...> }` | 컴파일 |
| 타입에 있는데 **수집**에 없다 | `snapshot()`이 객체 리터럴을 반환 — 필드 추가 = 즉시 에러 | 컴파일 (추가 코드 불요) |
| `useState`가 늘었는데 **타입**에 없다 | 소스 텍스트 검사 + `EXCLUDED`에 **제외 사유 필수** | 테스트 |
| 파서에 있는데 **왕복이 안 된다** | `Required<Snapshot>` 픽스처 → "전 필드가 기본값과 다름" 강제 → `toEqual` 3연쇄 | 테스트 |
| 저장은 되는데 **표시가 안 따른다** | 기점(1기점 → 0기점) 양끝 값 관통 | 테스트 (§7 Q5 의존) |
| 하이드레이션 레이스 | 게이트를 **state**(`presets === null`)로 바닥에 · `justApplied` ref를 그 위에 | 순수 함수로 판정 |

★**3연쇄의 이유** — 기본값으로 채운 픽스처로 왕복을 돌리면 아무것도 못 잡는다(기본값은 떨어져도 기본값이다).
★**state 게이트의 이유** — ref 게이트는 마운트 커밋의 이펙트 선언 순서에 의존해 지금은 자가 치유되지만,
M4에서 로드가 async가 되는 순간 창이 벌어져 **영구 소실**이 된다.

### 비평이 잡은 조용한 소실 5건 (착수 전 반영 필수)

1. ☠**저장소 부재 시 성공을 반환** — `storage()?.setItem(...)`은 접근 차단 브라우저에서 no-op으로 지나가는데
   `return true`다. 저장이 하나도 안 되는데 경고가 안 뜬다. → `if (storage() === undefined) return false`.
2. ☠**활성 슬롯이 손상되면 빈 프리셋으로 위장** — 목록엔 "12 엔트리"가 서 있는데 표가 비고, **첫 조작 한 번이
   자동 저장으로 그 슬롯을 덮어** 원본 회수 기회가 영구히 사라진다. → `openPresets`가 `broken`을 반환하고
   **자동 저장을 막는다**(표시만 붙이면 다음 조작에서 그대로 덮인다). 복사도 깨진 슬롯이면 아무것도 하지 않는다.
3. ☠**다중 탭에서 번호 재사용** — `seq`가 탭 메모리에만 있어 탭 B가 003을 만든 뒤 탭 A가 같은 003을 발급해
   **B의 빌드를 덮는다**. → 발급 직전 인덱스를 다시 읽어 `seq`를 합친다(최소 조치). 전면 동기는 §7 Q5.
4. ☠**이름이 인덱스에만 산다** → 슬롯에도 굽는다(§3).
5. ☠**`putIndex`가 직전 슬롯 실패를 지운다** — 쿼터로 슬롯 쓰기가 실패한 직후 전환하면 경고가 사라져
   사용자는 저장이 회복된 줄 안다. → 실패 플래그는 **성공적인 슬롯 쓰기에서만** 해제.

### 타입 함정 2건 (실측으로 재현됨)

- `BuilderSnapshot`은 **`interface`가 아니라 `type` 별칭**으로 선언한다 — 인터페이스는 암묵 인덱스
  시그니처가 없어 `Record<string, unknown>` 경유 파서가 TS2322/TS2352로 죽는다(`./dev gate` 레드).
- `lib.ts`의 `CardClass` 이관은 `export ... from` 순수 재수출로 하면 **lib.ts 자신이 깨진다**
  (지역 바인딩이 안 생기는데 `patchCardClass`가 그 이름을 쓴다). `import type` + `export type` 두 줄로.

### 파생 결정 (설계 판단 — 규약이 답을 정한 것)

- **체커 전역 키 4개 폐기** — 프리셋이 유일 정본(정본 두 벌 금지). 마이그레이션이 5키를 함께 승격한다.
- **다중 탭 최소 조치** — 번호 발급 직전 인덱스를 다시 읽어 `seq`를 합친다(재사용 = 남의 빌드를 덮는 경로).
  `storage` 이벤트 전면 동기는 이월.
- **하이드레이션 게이트 판정을 순수 함수로** — 저장소에 아일랜드를 렌더할 수단이 없다(jsdom·testing-library
  부재). 판정만 들어내 노드에서 테스트하고, 나머지는 헤드리스 실측으로 확인한다고 정직하게 적는다.

### 남은 미결 (마감 시점 — 착수는 막지 않는다)

**Q5. 배포 채널** — `localStorage`는 오리진 귀속이라 정식판(builder-engage)과 베타는 **저장소가 완전히
별개**다. 정식판에서 쌓은 프리셋은 본체로 흡수할 때 전부 사라지고, 구 키 승격도 채널마다 따로 돈다.
프리셋은 이 프로젝트 최초의 *사용자 실데이터*라 이 조항에 정면으로 걸리는 첫 피쳐다.
- 선택지 = A) 베타에만 먼저, 정식판은 M4 로그인 이후 · B) 정식판에도 내고 접이식 문구로 고지
  · C) v1에 JSON 내보내기/붙여넣기를 완충으로 추가
- 권장 = **A**. 이유 = 프리셋은 사용자가 시간을 들여 쌓는 물건이라 *"나중에 사라진다"* 를 고지로 때우면
  신뢰를 잃는다. A는 코드가 한 줄도 안 는다. C는 값어치가 있으나 스펙 밖 증설이고 M4가 그 역할을 맡는다.
- 안 정하면 — `./dev builder:publish` 시점을 정할 수 없고, 사용자가 정식판에 쌓기 시작한 뒤 A로 바꾸면
  그 데이터가 소실된다(되돌릴 수 없는 순서).

*정본 = 코드. 이 문서는 결정·근거·미결만 소유하고 구현 완료 시 `./dev gc`로 archive로 이송된다.*
