## 1. 프로젝트 정의

파이어 엠블렘 인게이지의 챕터를 체스판형 그리드로 재현하고, 유저가 **전략을 만들고(세팅+수순), 턴 단위로 탐색하고, 어디서든 공유**하는 웹 플랫폼. 모델은 lichess의 study/분석보드 — 국면을 세팅하고, 라인을 만들고, 링크 하나로 세계에 공유하는 문법을 FE로 옮긴다.

**시장 포지션:** FE 턴 리플레이/전략 공유 웹 도구는 한국·서구권 모두 선례가 없음(트라이앵글어택도 정적 배치도까지만 제공). LTC/효율 플레이 커뮤니티(현재 유튜브+포럼 텍스트로만 공유)가 정확한 수요층. 주 타깃은 해외(영어권) 우선, 한국 동시 지원.

**사이트 포지션 (확정): 종합 공략 허브이며, 체스판은 간판 히어로이자 서브 모듈이다.** 전략 보드가 얼굴이지만 구조적으로는 여러 모듈 중 하나이고, 타 공략 사이트처럼 방대한 정보(유닛·스킬·아이템 데이터베이스, 챕터 가이드 등)가 함께 담길 수 있다. Astro 정적 페이지 구조가 이미 이 확장을 지탱한다 — 데이터 파이프라인이 뽑는 JSON이 보드와 데이터베이스 페이지의 공용 원천이 되므로 추가 비용이 낮다. 모듈 명명은 천체 계열 네임스페이스로 통일한다.

**확장 전제 (설계 구속): 인게이지는 첫 타이틀일 뿐, 플랫폼은 FE 전 시리즈용이다.** 그리드 전술·턴제·유닛 스탯이라는 골격은 시리즈 공통이므로, 지금 내리는 모든 설계 결정은 타이틀 중립이어야 한다:

- **서비스명 타이틀 중립** — 이름에 engage·특정작 요소를 넣지 않는다 (닌텐도 상표 회피 겸)
- **네임스페이스** — 데이터·URL·기보 코드 전부 타이틀 ID로 구분: `/fe17/maps/m002`, 기보 헤더에 `game: fe17` + 룰 버전
- **룰 엔진 = 공용 코어 + 타이틀 플러그인** — 코어(보드·이벤트 소싱·스테핑·공유 킷·로스터 UI)는 게임 무관, 전투 공식·난수 모델·고유 시스템(인게이지/듀얼/무기 내구도 등)은 타이틀 모듈이 소유. GBA 3부작(FE6/7/8)은 데이터마인이 성숙해(트라이앵글어택도 커버) 현실적인 2호 확장 후보

세 히어로는 별개 기능이 아니라 **하나의 룰 엔진을 세 가지 난수 소스로 구동**하는 것: H1 = 기록된 결과 주입(리플레이), H2 = 실주사위/확률 표시, H3 = 전 분기 열거(탐색).

## 3. 검증 완료된 사실 (조사 + 파일럿 실증)

### 3-1. 데이터 — 결손 0% 확정 (본인 ROM 덤프에서 실물 검증됨)

Citron으로 2.0.0 업데이트 적용 romfs 덤프 완료. 파일럿 추출(UnityPy)로 다음을 실증:

- **dispos(유닛 배치) 전 맵**: 본편 M000–M026, 외전 S/G, **사룡의 장 E001–E006 포함**(DLC 콘텐츠가 업데이트 안에 있음이 확인됨). 유닛별 좌표·난이도별 레벨·장비·스킬·엠블렘·AI 파라미터 완비

### 3-2. 전투 로직 재현 가능성

- 결정 로직(이동범위·공속/추격·데미지·표시명중·체인어택 10%고정·브레이크·체인가드·지원/지형 보정): **100% 재현 가능** (커뮤니티 공식 + Calculator.xml로 이중 검증)

### 3-3. 공유 환경 제약

- 언퍼링 지원(디스코드·카톡·레딧·Discourse): og:image 카드 자동 전개. 미지원(디시): 전략 카드 이미지 + 링크 세트를 본문에 붙임

## 4. 시스템 아키텍처

### 4-1. 룰 엔진 (프로젝트의 심장)

`(국면, 행동, 난수소스) → 다음 국면` 순수 함수 라이브러리. TypeScript로 시작(뷰어 reducer와 공유), H3 탐색 성능 필요 시 핫패스만 Rust→WASM. 모든 상태는 이벤트 소싱: `state(N) = reduce(초기상태, 행동로그[0..N])`.

- 전략 데이터 = `초기 세팅(유닛 빌드+배치) + 선택적 행동 로그`. 챕터 공통 데이터는 공용 JSON, 유저 전략은 diff만 — 용량 극소
- 페이즈 경계 스냅숏 = 큰단위 스테핑 + O(1) 탐색 + 역스텝(직전 스냅숏에서 re-reduce)
- 리플레이 로그는 **결과값을 기록**(명중/필살/데미지/레벨업/적턴 행동 그대로) — 엔진은 검증용 (Wesnoth 재시뮬 방식의 버전 취약성 회피)

### 4-3. 공유 킷 (Share Kit)

공유 버튼 → 플랫폼 프리셋 → 클립보드/공유시트에 최적 페이로드:

- **전략 카드(Strategy Card)**: 공유 시점 클라이언트 캡처(보드 국면 + 선택 구역 줌 + 오버레이 토글 + 유닛 스탯 미니패널 + 턴 라벨 + 워터마크, 1200×630) → R2 저장 → og:image 겸 게시판 본문 이미지. 폴백: Workers+Satori 서버 생성
- 프리셋: 디시/카페(리치 HTML), 디스코드/카톡(링크=카드), 레딧/Discourse(링크/마크다운), 구형 포럼(BBCode), X(인텐트 URL), **기보 코드**(플레인 텍스트 직렬화 — 링크 검열 환경 백업 + 유닛 세트 공유와 인코딩 공유)
- 데스크톱 = 프리셋 복사(ClipboardItem 다중 MIME + 실패 시 2버튼 폴백), 모바일 = `navigator.share()` 네이티브 공유시트
- oEmbed 엔드포인트 구현(서구권 포럼 리치 임베드 + FEU 등과 iframe 화이트리스트 협의 여지)
- 링크에 `?src=` 태그로 프리셋별 유입 측정

### 4-4. 링크 랜딩 UX — "포커스 모드" (핵심 의도)

공유 링크를 누른 사람이 보는 첫 화면은 앱이 아니라 **전략 그 자체**다:

- 앱 셸·메뉴·설명 없이 **보드만 중앙에**, 조작은 이전/다음(←/→, 모바일 스와이프, 큰 버튼 2개)뿐
- 상단에 최소 라벨(챕터·난이도·턴)만. 탭/클릭하면 풀 UI(스탯 패널·로그·편집)로 점진 확장(progressive disclosure)
- **"이 앱은 뭐지?" 훅 = 인게임 충실 재현**: 공식 맵 아이콘·초상화·게임과 일치하는 전투 예보 수치가 첫 화면에서 바로 보이는 것. 게이머가 진짜임을 즉시 알아보게 하는 것이 마케팅의 전부
- 풀 앱으로의 전환 버튼("이 전략 편집해보기 / 나도 만들기")이 유일한 CTA

**속도 예산 — 비대칭 원칙: 스펙 상한은 첫인상(열람 경로)에만 적용한다**

성능 투자는 두 경로로 나눠 비대칭으로 배분한다:

- **열람 경로(공유 링크 → 첫 화면 → 스테핑)**: 엄격. 링크를 누른 사람은 아직 아무 가치도 투자하지 않았으므로 1초가 이탈을 가른다. 아래의 수치 목표를 릴리즈 게이트로 삼는다
- **제작 경로(전략 생성·편집, 전략 카드 렌더링, 링크 패키징, 솔버 실행)**: 여유 허용. 게시자는 전략판을 만드는 것 자체에 가치를 느끼는 투자된 유저라 수 초~수 분도 수용한다. 덕분에 카드 이미지는 고품질 렌더링을, 솔버는 긴 탐색을, 편집기는 기능 우선을 택할 수 있고 **열람 번들에서 제작 코드를 완전히 분리 로드**(code splitting)하는 근거가 된다

**열람 경로 수치 목표:**

- 목표: 공유 링크 클릭 → 보드 첫 렌더 **모바일 4G LCP < 1초**, 스테핑 반응 INP < 100ms
- 짧은 링크는 Workers가 엣지에서 **국면 스냅숏을 HTML에 인라인해 SSR** — 첫 페인트가 JS 로드를 기다리지 않음. 아일랜드 hydrate 후 조작 활성화
- 스테핑은 네트워크 제로: 챕터 로그 전체(수십 KB)가 이미 로드돼 있고 이전/다음은 메모리 내 reduce — 페이징 비용 0ms
- 에셋: 스프라이트·초상화 WebP + 첫 화면 등장 유닛만 우선 로드, 전략 카드 이미지를 LCP 플레이스홀더로 재사용(공유 카드와 첫 화면이 동일 구도라 체감 즉시성 극대화)
- 전 자원 Cloudflare 엣지 캐시(한국·북미·유럽 동일 체감), JS 예산: 포커스 모드 셸 < 100KB(gzip)

### 4-5. 뷰어 레이아웃 — 좌측 로스터 패널 (인게임 출격 대기 화면 문법)

- 보드 왼쪽에 **눈 포트레이트 칩 세로 로스터** — 인게임 출격 대기 화면과 같은 문법이라 게이머가 설명 없이 읽는다. 자군이 기본이고 탭으로 적군/NPC 로스터 전환
- 각 칩은 **폴딩 구조**: 접힘 = 눈 포트레이트 + 이름 + HP바 + 레벨. 펼침 = 상세 스펙(전 스탯, 장비, 스킬, 엠블렘·인게이지 상태, 지형·지원 보정 내역). 여러 명 동시 펼침 허용, 아코디언 애니메이션은 CSS로
- **보드와 양방향 동기화**: 로스터 칩 선택 ↔ 보드 말 하이라이트(+이동 범위 표시), 표시 값은 항상 현재 스텝 기준(스테핑하면 HP·상태가 같이 갱신). 전투 중인 유닛은 로스터에서 자동 강조
- 딥링크 `&u=` 파라미터가 이 패널의 펼침 상태를 복원
- 반응형: 데스크톱 = 좌측 고정 패널, 모바일 = 하단 시트(스와이프 업). **포커스 모드에서는 숨김** — 보드 우선 원칙 유지, 풀 UI 확장 시 등장
- 전사/이탈 유닛은 회색 처리로 로스터에 잔류(리플레이 감상 시 손실 파악용)

## 5. 다국어 (글로벌 퍼스트)

텍스트 3계층 전략:

1. **게임 용어층(~95%)**: ROM의 공식 명칭 12개 언어를 `names.{locale}.json`으로 — 번역 비용 0. 뷰어는 ID(PID/IID/SID) 기반 렌더링이라 언어 전환 = 사전 스왑
2. **UI 문자열층(수백 단어)**: 손번역. EN → KO → JA → zh-TW 순
3. **UGC층**: 전략은 데이터라 **언어 중립** — 한국 유저의 전략이 미국 유저에게 영어로 렌더링됨(작성자 메모만 원어). 이것이 글로벌 전략의 구조적 근거

URL은 언어 중립 ID + 로케일 프리픽스(`/en/maps/m002`), hreflang, 로케일별 정적 생성. 전략 카드도 로케일 렌더링(`?hl=` 변형). 폰트는 Noto Sans 로케일별 서브셋 분할 로드.

- 보드 문법: 군 색상 링(아군/적/NPC), 보스 뱃지, 드롭 보유 마커 — 인게임 문법 준수
- 아이콘류: `icon/weapon·skill·godsymbol` 번들에서 추출
- **맵 배경: 인게임 미니맵 차용 (확정)** — Terrain.xml에 지형별 공식 미니맵 색상이 데이터로 들어 있으므로, 타일별 지형ID + 공식 미니맵 색으로 보드 배경을 자체 렌더링한다. 게이머에게 즉시 익숙한 인게임 미니맵 룩을 재현하면서도 3D 맵 렌더 이미지를 립하지 않아 저작권상 가장 안전하고, 데이터 기반이라 전 맵 자동 생성·경량(이미지 불필요, DOM/SVG 타일)·다크모드 대응까지 해결. 지형 정보(회피/방어 보정)가 배경색으로 자연스럽게 읽히는 부수 효과

## 7. H3 (최적 탐색) — AI 스펙 확정

**"AI"의 정의: LLM이 아니라 탐색 알고리즘이다.** 최적 세팅/수순 탐색은 expectimax·빔서치·MCTS 계열의 자체 구현(오픈소스) 문제이며, GPU도 모델 서빙도 필요 없다. 이 정의 하나로 비용 문제가 근본적으로 해소된다.

**실행 위치와 비용:**

- **기본: 유저 브라우저에서 실행** (WebWorker → 필요 시 WASM). 룰 엔진이 순수 함수라 그대로 탐색 코어가 됨. **서버 비용 0원, 유저가 늘수록 연산력도 같이 늘어남**
- **심층 분석: 로컬 러너 배포** — 무거운 탐색(챕터 솔버, 장시간 탐색)은 다운로드형 CLI/스크립트(Node 또는 Rust 바이너리)로 제공. **입력 = 기보 코드, 출력 = 기보 코드.** 유저가 자기 PC에서 돌리고 결과 코드를 사이트/게시판에 붙여넣는다 — 체스에서 유저들이 Stockfish를 로컬로 돌려 분석을 공유하는 관행과 동일한 문법
- **후순위 옵션: 자발적 분산 분석망** — lichess의 fishnet(자원봉사자들이 클라이언트를 돌려 서버 분석 큐를 처리)이 검증된 선례. 커뮤니티가 커지면 같은 로컬 러너에 "큐에서 일감 받기" 모드만 추가하면 됨
- **서버에서 탐색을 돌리는 옵션은 채택하지 않는다** (무료 티어 CPU 제한 초과, 비용 통제 불가)

### 7-2. LLM 연동 계층 — "외부 LLM이 전략을 만들어 붙여넣는" 경로

탐색 알고리즘(위)과 별개로, ChatGPT/Claude 같은 **외부 LLM을 전략 생성기로 쓰는 경로**를 공식 지원한다. 원칙: **LLM은 우리 서버에서 돌리지 않는다** — 유저가 자기 LLM(웹 챗, API)에게 시키고, 결과물을 우리 앱에 붙여넣는 구조. 비용 0, 인프라 0.

구성 요소 4가지:

1. **오픈소스 공개**: 룰 엔진 + 기보 포맷 스펙 + 챕터 데이터 스키마를 GitHub에 공개. LLM이 웹에서 학습·참조할 수 있고, 유저가 "이 스펙 문서를 읽고 M002 매드닝을 3턴에 깨는 전략을 기보 코드로 작성해줘"라고 시킬 수 있는 전제가 됨
2. **LLM 친화적 기보 포맷**: 기보 코드를 사람도 LLM도 읽고 쓸 수 있는 평문 구조(예: JSON/텍스트 표기)로 설계하고, 프롬프트에 통째로 넣을 수 있는 **"컨텍스트 팩" 내보내기** 버튼 제공 — 현재 국면 + 규칙 요약 + 포맷 스펙 + 목표를 한 번에 복사 → 아무 LLM에나 붙여넣기
3. **검증기(핵심 안전장치)**: LLM은 규칙 위반 수(불법 이동, 사거리 초과, 없는 스킬)를 지어내므로, 붙여넣은 전략을 **룰 엔진이 행동 단위로 합법성 검증**하고 위반 지점을 사람이 읽을 수 있는 오류 메시지로 반환. 유저는 그 오류를 다시 LLM에게 붙여넣어 고치게 함 — "LLM이 제안하고 엔진이 심판하는" 반복 루프. 이 검증기 덕분에 어떤 LLM이 얼마나 틀리든 앱의 정확성은 훼손되지 않음
4. **어드민 원클릭 (Claude 직결)**: 운영자용으로는 붙여넣기 과정도 없앤다 — 앱을 **MCP 서버**로 노출(현재 국면 조회, 전략 검증, 시뮬레이션 실행, 전략 저장을 도구로 제공)하면 Claude(데스크톱/Cowork/Code)가 보드를 직접 읽고 쓸 수 있어, 어드민은 "이 맵 전략 짜줘" 한마디로 끝. 대안 겸 1단계 구현: 뷰어의 "Claude에 보내기" 버튼 = 컨텍스트 팩 자동 복사 + Claude 열기(원클릭 반, 개발 공수 최소). **제약(확정): Anthropic API는 사용하지 않는다** — 어드민의 Claude 이용은 Max 플랜 구독 표면(Claude 데스크톱/Cowork/Claude Code)로만 하며, MCP는 구독 클라이언트가 접속하는 방식이라 API 과금 없이 정확히 이 제약 안에서 동작한다. 서버가 Claude API를 호출하는 설계는 전면 금지

일반 유저용 LLM 조언 기능을 앱 안에 내장하는 것은 MVP 제외. 도입하더라도 서버 호스팅 금지 원칙 — 브라우저 내 실행(WebLLM/WebGPU) 또는 유저 본인 API 키 방식만 검토.

**단계 계획:**

1. **단일 교전 최적화** (샌드박스 내장): 확정킬 판정, 위험범위, 기대 데미지 정렬 — 전수 열거로 즉시 가능. 브라우저에서 밀리초 단위
2. **1턴 옵티마이저**: expectimax + 가지치기, "최적" 정의를 유저가 선택(기대값 vs 성공률 임계선 — LTC 문법). WebWorker 규모
3. **챕터 솔버(장기)**: 로컬 러너 영역. 병목은 적 AI 모델 — dispos AI 파라미터로 근사 모델 구축 → **유저 공유 리플레이의 적턴 기록이 검증·보정 데이터**가 되는 선순환(H1이 H3를 먹여 살리는 구조)

### 10-1. 백엔드: **Cloudflare Workers + KV + R2 + D1** (계정 계층 요구로 D1 정식 편성)

| 기준 | 평가 |

### 10-2. 계정·보존 계층 — "로컬까지 게이트 제로, 서버 게시는 로그인" (2026-08-16 사용자 재확정)

★**기본 룰: 로컬 행위는 전부 무계정.** 열람·스테핑·전략 제작·기보 내보내기/가져오기·**내 보관함(브라우저 저장, 재방문 시 심리스 복구·이어 플레이)**까지 로그인 불필요. **타인에게 링크를 공유(서버 게시·짧은 링크 발급)하는 순간부터 로그인 필요** — 우리 서버 자원을 쓰는 행위가 게이트 경계다. (2026-08-15 "무계정 공유+Turnstile 발급" 결정을 대체)

| 티어 | 이용자 | 제공 기능 | 저장 위치 |
|---|---|---|---|
| **T0 무계정 (기본)** | 모든 방문자 | 열람·스테핑·제작·기보 내보내기/가져오기·**내 보관함**(재방문 심리스 복구) | localStorage |
| **T1 소셜 로그인** | 게시자 | **링크 공유(짧은 링크 발급)·기보 서버 아카이빙(영구 보관)**·기기 간 동기화·출전멤버 프로필·내 전략 관리(수정·비공개)·팔로우·컬렉션 | KV(공유분) + D1 |
| **T2 커뮤니티** | 규모 형성 후 | 전략 갤러리 탐색·검색, 추천, 랭킹 — ★**레이트·랭킹 설계는 미결** | D1 + Workers Cron 주기 집계 |

- **게스트 로컬 보관 용량·한계(정직 표기)**: localStorage는 오리진당 ~5MB급(브라우저별 상이) — 기보는 챕터당 수십 KB 설계 목표(§4-4)라 수십 개 이상 보관 가능, 실측치는 M3 샘플로 기록. 부족해지면 IndexedDB 승격(브라우저 디스크 여유 기반 쿼터, 수백 MB급) — 저장 계층을 함수로 격리해 교체 여지 확보. ☠영구 보장 아님: 브라우저 정리·Safari의 스크립트 저장소 7일 미방문 삭제 정책·기기 변경으로 유실 가능 — **유실 방지가 로그인 업그레이드의 핵심 가치**
- **인증: 소셜 로그인 전용** (자체 이메일/비밀번호 없음). 라이브러리 = **better-auth**(Workers+D1 어댑터, 무료·자체 호스팅). 프로바이더는 Google·Discord 우선, 이후 X·Kakao·Naver 순차. **공유가 로그인 뒤로 가면서 better-auth+D1은 M4(공유) 시점에 편입**
- **무계정→계정 승계 = 즉시 저장**: 로그인 즉시 로컬 보관함의 전략 전부를 서버 DB(D1)로 자동 저장·귀속(claim) — 플레이 데이터 유실은 UX 치명이므로 수동 단계 없이 즉시. 이후에는 로컬+서버 이중 저장(동기화)
- **어뷰즈 방어**: [축소] 무계정 서버 쓰기가 없어져 발급용 Turnstile 불필요 — 로그인 계층 어뷰즈가 발현하면 재검토. 읽기는 전부 공개
- 비용: better-auth·Cron 무료, D1 5GB 무료 — 기준 2 유지

### 10-3. LLM 왕복 패키징 — 컨텍스트 팩 왕복

계획서 7-2 그대로: 보드의 **오픈소스 코드(룰 엔진+ephemeris 스펙)와 프롬프트를 한 덩어리로 패키징**하는 "컨텍스트 팩" 버튼 → 유저가 아무 외부 LLM에나 붙여넣기 → 받아온 전략을 엔진 검증기가 심판 → 오류 메시지를 다시 LLM에 왕복. 서버 LLM 없음, 어드민은 MCP/Max 플랜 표면 전용. 이 요구는 **저장소 공개(오픈소스)가 전제**이므로 init 시점부터 공개 저장소로 시작한다.

### 10-4. 적 행동·위임(자동진행) 시뮬레이션 — 인게임 데이터 기반

★**요구: 적턴 행동과 위임(조작 없는 자동진행) 모두 인게임 데이터대로 시뮬레이션한다.** 기존 계획("적턴은 유저가 가정 수순 입력")에서 한 단계 상향.

- **근거 데이터는 전부 확보됨**: 덤프의 `AI.xml`(AI 루틴 정의) + dispos 유닛별 AI 파라미터(`AI_ActionName/Val`·`AI_MindName`·`AI_AttackName`(타겟 선호)·`AI_MoveName`·`AI_MoveLimit`·`AI_Priority`·`AI_BattleRate`·`AI_BandNo`). 어떤 적이 어떤 루틴·행동조건·타겟 우선순위를 갖는지는 **데이터 그대로 100% 반영 가능**
- **정직한 한계(no-fiction)**: 루틴을 실행하는 평가 엔진(동점 처리·이동 타일 선택의 세부)은 코드(IL2CPP) 영역이라 공개 문서가 없음 → **파라미터는 정본 그대로, 평가함수는 실측 보정 모델**로 시작한다. 위임(자동전투)도 같은 AI 루틴 체계를 쓰므로 동일 모듈이 담당
- **수렴 루프**: H1 리플레이 코퍼스(유저가 기록한 실제 적턴·위임 행동)가 AI 모델의 검증·보정 데이터 — 리플레이가 쌓일수록 자동진행 정확도가 인게임에 수렴하는 구조(계획서 7절 선순환의 구체화). 불일치 케이스는 회귀 테스트로 박제
- **구현 위치**: `packages/engine/src/ai/` — 룰 엔진과 같은 순수 함수 계약(`(국면, AI파라미터) → 행동`), 난수 소스 주입 동일
- 효과: 샌드박스(H2)에서 "적턴 자동 재생" · 위임 시뮬레이션 · 솔버(H3)의 적 모델이 전부 이 모듈 하나를 공유
