# 인게임 충실도 검증 체계 — QA 비용의 구조적 절감

작성 2026-08-16. 발단 = 베타 실기에서 이동 룰 결함 2건(무제한 재이동·잠정 이동 부재)이 **사용자 주의력으로만** 발견됨.
산식·룰의 미세한 오차는 유저가 신뢰를 걸고 쓰는 도구에서 치명이며, 출시 후 QA 비용은 기하급수로 는다.
목표 = **개발 단계에서 오차를 기계적으로 잡는 다층 방어**.

## 0. 오늘 결함의 사후 분석 (왜 못 잡았나)

| 결함 | 근본 원인 |
|---|---|
| 이동 무제한 재이동 | "활성화당 이동 1회"라는 기전이 **스펙 목록에 존재하지 않았다** → 테스트도 앵커도 없음 |
| 잠정 이동 부재 | 이동 확정 시점이라는 **UX 문법이 미스펙** — 엔진 룰과 별개의 재현 대상인데 목록에 없었다 |

교훈: 도구(테스트·코퍼스)는 이미 있었다. **없던 것은 "검증해야 할 것의 전수 목록"**이다.

## 1. 오차의 분류 (방어층은 분류별로 다르다)

- **C1 산식 오차** — 데미지·명중·경험치 수식, 반올림, 적용 순서
- **C2 룰·상태기계 오차** — 이동·행동 합법성, 브레이크, 체인어택, 턴 구조 (오늘 결함)
- **C3 데이터 해석 오차** — 컬럼 의미 오독 (전례: 통행 = Prohibition 아님 · 재이동 Power = 칸수(남은 이동력 아님))
- **C4 UI-엔진 불일치** — UI가 엔진과 다른 로직을 중복 보유해 생기는 표류 (오늘 이동 예산 로직이 UI에 중복됨 — 현존 리스크)
- **C5 회귀** — 리팩터가 기존 정답을 깨뜨림

## 2. 방어층 설계 (우선순위 순)

### 2-1. ★기전 장부 (Fidelity Ledger) — `registers/fidelity.md` [C1~C4의 전제]

인게임 기전을 **전수 열거**하고 건별 상태를 기록하는 장부. 커뮤니티 가이드·데이터마인 목차 기준으로 초기 작성.

```
| 기전 | 상태 | 근거·앵커 |
상태 ∈ 구현+실기앵커 / 구현+미검증(가정 명시) / 미구현(표기됨) / 미룸(조건)
```

- 효과 1: **"몰라서 못 잡는" 부류를 소멸** — 목록에 있는데 미검증이면 최소한 알고 있는 리스크다
- 효과 2: no-fiction "±1 가능" 배지·미구현 표기의 데이터 원천 (정직 표기를 기전 단위로 기계화)
- 효과 3: QA 우선순위 = 사용 빈도 높은 기전부터
- 운용: 신규 기전 구현 PR = 장부 갱신 필수(고아 금지 규약과 동형). 결함 발견 = 해당 기전 상태 강등 + 앵커 추가

### 2-2. ★미러 플레이 프로토콜 — 실기 대조의 최고 효율 형태 [C1·C2·C3]

실기(에뮬)와 FESim 샌드박스를 **나란히 놓고 같은 수순을 동시 진행**한다.

- 매 스텝 비교물: 이동 범위 타일 · 예보 수치 전항 · 전투 결과(같은 결과 롤 주입은 불가하니 명중·데미지 값) · HP·경험치·레벨업
- **불일치 발견 즉시 그 국면이 재현 케이스**: 샌드박스 기록(.eph)이 자동으로 남으므로 리포트 = 기보 첨부 완료 상태
- 1챕터 완주 = 이동·전투·성장·턴 구조 수백 판정의 일괄 앵커. 스크린샷 코퍼스보다 밀도가 수십 배
- 완주 후 기보를 `corpus/`에 박제 → 회귀 테스트가 영구 방어 (C5)
- 비용 = 사용자 플레이 시간(챕터당 1~2시간 추정, 실측 후 갱신). 도구 비용 ≈ 0 (레코더 기존)

### 2-3. 속성 기반 테스트 (fast-check) + UI-엔진 로직 단일화 [C2·C4·C5]

- 엔진 불변식을 무작위 국면·행동으로 융단폭격: HP ∈ [0,max] · 명중 ∈ [0,100] · 라운드트립 결정성 ·
  "movementRange가 내놓은 전 타일 = reduce가 수락하는 전 타일"(합법성 쌍대) · 무작위 로그 fuzz(크래시 0 + verify 자기일관)
- ★UI 중복 로직 회수: 이동 예산 판정을 엔진 `moveBudget(u)`로 수출하고 BoardIsland가 소비 (오늘 생긴 중복 제거 — C4의 실존 사례)

### 2-4. 데이터 해석 게이트 [C3]

신규 컬럼 해석 1건 = 근거 1건 명시(공식 도움말 텍스트 대조 · 전수 통계 · 실기 캡처) — 독스트링+장부에 기록.
오늘 재이동에서 이미 수행한 절차(Power ↔ 도움말 "행동 후 N칸" 대조)를 **규약으로 승격**.
보조: SerenesForest 등 커뮤니티 데이터마인과의 자동 대조 스크립트 확장(스탯 36명 전수 대조의 일반화 — 아이템·성장률·스킬 수치).

### 2-5. 신고 루프 (베타 유저 = 분산 QA) [전 분류]

보드에 "이상 신고" 버튼: 현재 기보(.eph)+국면 주소를 자동 첨부 — **리플레이가 결정론이라 모든 신고가 완전 재현 케이스**.
초기(무서버)는 클립보드 복사 + 이슈 템플릿, M4 서버 게시 후 원클릭화.

### 2-6. 에뮬레이터 자동화 [미룸]

TAS식 입력 스크립트로 예보 화면 전수 채굴 등. 고비용 — **미룸, 발현 조건 = 미러 플레이로 코퍼스 수집이 병목이 될 때**.

## 3. 편입 계획(안) — M3.5 "검증 기반" 소마일스톤

1. `registers/fidelity.md` 초판 (기전 전수 열거 — 커뮤니티 가이드 목차 기반, 반나절)
2. `moveBudget` 엔진 수출 + UI 소비 (중복 회수, 소규모)
3. fast-check 편입 + 불변식 3종(합법성 쌍대·라운드트립·로그 fuzz)
4. 미러 플레이 1회차: M002 루나틱 완주(사용자) → 불일치 전수 기록 → 기보 코퍼스 박제
5. 신고 버튼 최소형(클립보드) — M4로 미뤄도 무방

## 4. 미결 (사용자 결정 필요)

- **Q1 미러 플레이 채택 여부·범위**: 사용자 플레이 시간이 비용. 권장 = M002 1챕터 1회(최고 효율 앵커). 안 정하면 = 실기 대조가 스크린샷 단발에 머묾
- **Q2 기전 장부의 노출 범위**: 내부 장부만 vs UI 배지(미구현·미검증 기전을 유저에게 표시)까지. 권장 = 내부 우선, UI 배지는 M4 공유 전 필수(신뢰 자산화)
- **Q3 M3.5 편입 vs M4 병행**: 권장 = M3.5로 분리(§3의 1~4), M4 착수 전 수행 — 공유 기능이 열리기 전이 오차 수정의 최저 비용 시점
- **Q4 property 테스트 상시 게이트 여부**: fast-check를 ./dev done에 넣으면 느려질 수 있음(시드 고정·케이스 수 조절로 완화). 권장 = 소케이스 상시 + 대케이스 야간/수동
