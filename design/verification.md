# 인게임 충실도 검증 체계 — QA 비용의 구조적 절감

작성 2026-08-16. 발단 = 베타 실기에서 이동 룰 결함 2건(무제한 재이동·잠정 이동 부재)이 **사용자 주의력으로만** 발견됨.
산식·룰의 미세한 오차는 유저가 신뢰를 걸고 쓰는 도구에서 치명이며, 출시 후 QA 비용은 기하급수로 는다.
목표 = **개발 단계에서 오차를 기계적으로 잡는 다층 방어**.

## 0. 오늘 결함의 사후 분석 (왜 못 잡았나)

| 결함 | 근본 원인 |
|---|---|
| 이동 무제한 재이동 | "활성화당 이동 1회"라는 기전이 **스펙 목록에 존재하지 않았다** → 테스트도 앵커도 없음 |
| 잠정 이동 부재 | 이동 확정 시점이라는 **UX 문법이 미스펙** — 엔진 룰과 별개의 재현 대상인데 목록에 없었다 |

교훈: 도구(테스트·코퍼스)는 이미 있었다. **없던 것은 "검증해야 할 것의 전수 목록"**이다.

## 1. 오차의 분류 (방어층은 분류별로 다르다)

- **C1 산식 오차** — 데미지·명중·경험치 수식, 반올림, 적용 순서
- **C2 룰·상태기계 오차** — 이동·행동 합법성, 브레이크, 체인어택, 턴 구조 (오늘 결함)
- **C3 데이터 해석 오차** — 컬럼 의미 오독 (전례: 통행 = Prohibition 아님 · 재이동 Power = 칸수(남은 이동력 아님))
- **C4 UI-엔진 불일치** — UI가 엔진과 다른 로직을 중복 보유해 생기는 표류 (오늘 이동 예산 로직이 UI에 중복됨 — 현존 리스크)
- **C5 회귀** — 리팩터가 기존 정답을 깨뜨림

## 2. 방어층 설계 (우선순위 순)

### 2-1. ★기전 장부 (Fidelity Ledger) — 정본 = `packages/shared/src/fidelity.ts` [C1~C4의 전제]

인게임 기전을 **전수 열거**하고 건별 상태를 기록하는 장부. 커뮤니티 가이드·데이터마인 목차 기준으로 초기 작성.
★정본은 **타입드 코드**(산문 장부 이중화 금지 — 불변식 1): UI 배지·문서가 전부 이 테이블을 소비한다.

```ts
interface FidelityEntry {
  id: string;              // "movement.once-per-activation" 같은 기전 키
  label: { en: string; ko: string };
  status: "anchored" | "implemented" | "assumed" | "absent" | "deferred";
  // anchored = 실기 앵커 有 · implemented = 구현+미검증 · assumed = 가정 명시 · absent = 미구현(표기) · deferred = 미룸
  evidence?: string;       // 근거·앵커 포인터(테스트명·코퍼스 케이스·도움말 키)
}
```

- 효과 1: **"몰라서 못 잡는" 부류를 소멸** — 목록에 있는데 미검증이면 최소한 알고 있는 리스크다
- 효과 2: no-fiction "±1 가능" 배지·미구현 표기의 데이터 원천 (정직 표기를 기전 단위로 기계화)
- 효과 3: QA 우선순위 = 사용 빈도 높은 기전부터
- 운용: 신규 기전 구현 = 장부 갱신 필수(고아 금지 규약과 동형). 결함 발견 = 해당 기전 상태 강등 + 앵커 추가
- **UI 배지(확정: 지금 편입)**: (a) 보드·포커스 페이지에 "재현 상태" 요약 진입점(예: 브리핑/푸터의 상태 뱃지 → 기전 목록 뷰)
  (b) 미재현(absent)·가정(assumed) 기전이 화면에 실체로 드러나는 지점(스킬 칩 등)은 회색/점선 + 툴팁. 상세 UI는 구현 시 확정

### 2-2. ★미러 플레이 프로토콜 — 실기 대조의 최고 효율 형태 [C1·C2·C3]

실기(에뮬)와 FESim 샌드박스를 **나란히 놓고 같은 수순을 동시 진행**한다.

- 매 스텝 비교물: 이동 범위 타일 · 예보 수치 전항 · 전투 결과(같은 결과 롤 주입은 불가하니 명중·데미지 값) · HP·경험치·레벨업
- **불일치 발견 즉시 그 국면이 재현 케이스**: 샌드박스 기록(.eph)이 자동으로 남으므로 리포트 = 기보 첨부 완료 상태
- 1챕터 완주 = 이동·전투·성장·턴 구조 수백 판정의 일괄 앵커. 스크린샷 코퍼스보다 밀도가 수십 배
- 완주 후 기보를 `corpus/`에 박제 → 회귀 테스트가 영구 방어 (C5)
- 비용 = 사용자 플레이 시간(챕터당 1~2시간 추정, 실측 후 갱신). 도구 비용 ≈ 0 (레코더 기존)

### 2-3. 속성 기반 테스트 (fast-check) + UI-엔진 로직 단일화 [C2·C4·C5]

- 엔진 불변식을 무작위 국면·행동으로 융단폭격: HP ∈ [0,max] · 명중 ∈ [0,100] · 라운드트립 결정성 ·
  "movementRange가 내놓은 전 타일 = reduce가 수락하는 전 타일"(합법성 쌍대) · 무작위 로그 fuzz(크래시 0 + verify 자기일관)
- ★UI 중복 로직 회수: 이동 예산 판정을 엔진 `moveBudget(u)`로 수출하고 BoardIsland가 소비 (오늘 생긴 중복 제거 — C4의 실존 사례)

### 2-4. 데이터 해석 게이트 [C3]

신규 컬럼 해석 1건 = 근거 1건 명시(공식 도움말 텍스트 대조 · 전수 통계 · 실기 캡처) — 독스트링+장부에 기록.
오늘 재이동에서 이미 수행한 절차(Power ↔ 도움말 "행동 후 N칸" 대조)를 **규약으로 승격**.
보조: SerenesForest 등 커뮤니티 데이터마인과의 자동 대조 스크립트 확장(스탯 36명 전수 대조의 일반화 — 아이템·성장률·스킬 수치).

### 2-5. 신고 루프 (베타 유저 = 분산 QA) [전 분류]

보드에 "이상 신고" 버튼: 현재 기보(.eph)+국면 주소를 자동 첨부 — **리플레이가 결정론이라 모든 신고가 완전 재현 케이스**.
초기(무서버)는 클립보드 복사 + 이슈 템플릿, M4 서버 게시 후 원클릭화.

### 2-6. 에뮬레이터 자동화 [미룸]

TAS식 입력 스크립트로 예보 화면 전수 채굴 등. 고비용 — **미룸, 발현 조건 = 미러 플레이로 코퍼스 수집이 병목이 될 때**.

### 2-7. ★IL2CPP 실행파일 정적 분석 — "실측 전용" 항목의 정본 확인 경로 (2026-08-17 개통)

미러 플레이가 유일 경로라던 항목들(§4 실측 대기 목록)의 **상당수가 실행파일 코드에 있다**. FE 인게이지는
Unity IL2CPP 게임이라 exefs `main`(C#→C++ AOT)에 `global-metadata.dat`를 짝지으면 클래스·메서드 심볼이
복원된다. 이 경로가 개통되면 명중 난수·필살·경험 등은 **실측(확률적·표본 필요)이 아니라 코드 판독(결정적)**으로
정본을 확정할 수 있다. no-fiction 위배 아님 — 실행파일은 게임 로직의 1차 정본이다(romfs 데이터와 동급).

- **부트스트랩·절차 정본 = `tools/exefs/README.md`** (추출기 소스 = LibHac 참조 C#, 티켓 임포트 포함).
- **산출물**(저장소 밖 `~/fesim_data/`): `exefs/main`(5.0.0·NSO0·47MB) · `il2cpp_out/{dump.cs,script.json,il2cpp.h,DummyDll/}`.
  버전 정합 = main·global-metadata 둘 다 5.0.0(메타데이터 v27, romfs 데이터마인 정본과 동일 빌드).
- **함수 본문 판독 = `tools/exefs/nso_disasm.py`**(2026-08-17 개통 — Ghidra·JDK 불요). NSO의 LZ4 `.text`를
  디컴프레스해 RVA 구간만 aarch64 디스어셈블하고, `BL` 분기처에 `script.json` 심볼명을 붙인다.
  ☠간접 호출(`BLR`·델리게이트)은 이름이 안 붙으므로 vtable 오프셋·바인딩 지점을 dump.cs로 역추적해야 한다 —
  실제로 `BattleMath.RandomCheckHit`은 **`BattleMath.Probability` 델리게이트로 tail-call**한다(명중 판정이
  주입 가능한 함수라는 구조적 발견, 2026-08-17). 판독 보고서 = `~/fesim_data/extracted/il2cpp/`.
  우선 대상(`BattleCalculator`):

  | 미결 항목(§4) | 정본 함수(dump.cs 확인) |
  |---|---|
  | 명중 난수 모델(1RN/2RN/sin) | `BattleCalculator.RandomCheckHit(int ratio)` |
  | 필살 판정·배수 | `CalcAttackHit(BattleInfoSide, BattleInfoSide, out int critical)` |
  | 戦闘経験倍率 적용점·반올림 | `CalcExp(FuncExp1, ...)` · `CalcExp(FuncExp2, ...)` |

  | 독 티어 승격 하드코딩 | 상태이상 부여 경로(BadState 처리) — 심볼 탐색 대상 |
  | 신룡의 장 적 레벨 스케일링 | 유닛 생성·레벨 결정 경로(`units.divine-paralogue-level`) |

  ★**수정구간 발생 시 = 엔진 + 룰북(fidelity.ts) 동시 수정**(§2-5·플랜 규약 동일). 코드 판독으로 확정한

   플레이는 사용자, 불일치 기록·수정·기보 코퍼스 박제는 세션 몫. 완주 기보 = `packages/engine/tests/` 회귀 코퍼스 편입 +
